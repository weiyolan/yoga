# Yoga, Zen & Tonic: Sanity Studio

The CMS where Rita & Philippe edit the website. It's a standalone Studio (Sanity v6) next to the Next.js app. Queries and types live in `../sanity/` so the frontend can use them.

```
studio/                  this Studio (schemas, desk structure, seed)
sanity/                  shared with the Next.js app
  site.config.ts         languages + default language + API version
  queries.ts             GROQ for every page (defineQuery)
  types.ts               generated by TypeGen; don't edit
  client.ts, fetch.ts    typed fetcher
  image.ts               urlFor(), respects the hotspot
```

## Content model

| Studio | Type | Notes |
|---|---|---|
| Instellingen | `settings` (singleton) | name, slogan, e-mail, GSM, socials, default sign-up link, default SEO |
| Home | `homePage` (singleton) | opening image, intro (≤ 400 chars), featured retreat (empty = next one), ≤ 3 testimonials, "who are we" |
| **Fotobank** | `mediaItem` | **every photo is stored once**: hotspot, alt text, title, description, place, date, categories, retreat, "show in gallery", "highlighted". Pages only *reference* photos. |
| Pagina's | `retreatsPage` · `lessonsPage` · `coachingPage` · `aboutPage` · `galleryPage` · `contactPage` (singletons) | opening image + page-specific fields + SEO. The weekly schedule lives on `lessonsPage`. |
| Retreats | `retreat` | groups follow the detail page: basics · in a nutshell · the place · the people · programme · practical · closing. Komend / Voorbij is **derived from `endDate`**, never stored. |
| Team & begeleiders | `person` | Rita, Philippe, guest guides (portrait + optional "object" photo for the hover swap) |
| Lessen | `yogaClass`, `studio` | styles (what / for whom / where), studios |
| Testimonials | `testimonial` | quote ≤ 200 chars, optional link to a retreat |

Design rules (from the agent-toolkit skills `sanity-best-practices` and `content-modeling-best-practices`):

- **Model data, not presentation.** There are no layout or colour fields. The one exception is `highlight` on a photo (a bigger mosaic tile), which is an editorial choice.
- **Localization is field-level.** It uses `sanity-plugin-internationalized-array` (v5 stores `language` on each item). Dutch is required and English is optional; queries fall back to Dutch.
- **Singletons have fixed ids and are locked in Structure.** They can't be created, duplicated or deleted.
- **Reuse goes through references.** Photos, people, studios, styles and testimonials are documents. Small page parts are embedded objects: hero, SEO, price, programme item, schedule slot.
- **Soft length limits keep texts short.** These are warnings, not errors. The client's main complaint about other sites was "te veel tekst".
- **List fields are one textarea per language, one item per line.** This applies to highlights, included, not included and contact subjects. Queries return them as `string[]`.
- **Video is never stored as a Sanity file.** Use a Vimeo or Mux URL; the photo acts as the poster.

## Languages

All languages are set in `../sanity/site.config.ts`:

```ts
export const languages = [
  { id: "nl", title: "Nederlands" },
  { id: "en", title: "English" },
] as const;
export const defaultLanguage = "nl" as const;
```

To add a language, add a line here. It then appears in every localized field in the Studio and in the `Lang` type. After that, run `npm run typegen`.

## Typed fetcher

```ts
import { sanityFetch } from "@/sanity/fetch";
import { RETREAT_BY_SLUG_QUERY } from "@/sanity/queries";

const retreat = await sanityFetch({
  query: RETREAT_BY_SLUG_QUERY,
  params: { slug },          // required: the query uses $slug
  lang: "en",                // typed to site.config languages; default "nl"
  tags: ["retreat"],         // optional Next.js cache tags
});
retreat?.title;              // string | null, inferred, no generics
```

- **Result types are inferred.** TypeGen registers every `defineQuery` in `SanityQueries`. Query fragments are `as const`, so TypeScript sees the exact query string.
- **Params are checked.** `$lang` is always injected for you. Any other `$param` in the query is required, and a missing or unknown one is a compile error.
- **The checks are compiled with the root project.** `sanity/fetch.typecheck.ts` is picked up by `npx tsc --noEmit` at the repo root.

## Setup (once)

```bash
cd studio
npm install
npx sanity login
cp .env.example .env           # project 1pbhk0to · dataset production · SANITY_AUTH_TOKEN (write token, seed only)
npx sanity cors add http://localhost:3000 --credentials
npm run seed                   # wireframe content + photos from seed/images
npm run dev                    # http://localhost:3333
npm run deploy                 # yogazentonic.sanity.studio
```

The frontend needs `NEXT_PUBLIC_SANITY_PROJECT_ID` and `NEXT_PUBLIC_SANITY_DATASET`. `@sanity/client` v8 needs Node ≥ 22.12. Finally, invite Rita & Philippe as **Editor** under sanity.io/manage → Members.

## Scripts

| | |
|---|---|
| `npm run dev` / `build` / `deploy` | Studio |
| `npm run typegen` | extract the schema and regenerate `../sanity/types.ts` (run after changing a schema or a query) |
| `npm run validate` | schema validation |
| `npm run seed` | idempotent seed. `npx sanity exec scripts/seed.ts -- --dry` prints it without writing |
